# 宿舍冰箱智能管理系统（fridge_pi）

> 创客教育 × 校园总务合作项目：用真实可用的系统替代宿舍冰箱的纸质登记。
> 学生微信登录管理自己的物品，冰箱触控屏拍照登记存取，宿管拍照盘点、依规清理留痕。

三端架构，全部署在同一台树莓派 5 上（方案 B）：

```
┌─────────────────────── 树莓派 5（校园内网） ───────────────────────┐
│  pi/   锁控+摄像头+分类+触控屏 :8000  ←轮询(X-Pi-Secret)→          │
│  server/  小程序后端 FastAPI+SQLite :8001  ←HTTPS→  微信小程序     │
└───────────────────────────────────────────────────────────────────┘
```

## 核心业务流程

| 环节 | 方式 |
|---|---|
| 登录 | 微信登录（code2session），首次绑定姓名+房间号；未登录不可用任何功能 |
| 存入 | 只能在冰箱触控屏：屏幕出登录码 → 小程序扫码确认身份 → 拍照识别分类 → 确认登记 → 自动打印 40×30mm 标签 + 电磁锁开锁（60s 自动落锁），物品直接归属登录者 |
| 取出 | 三条路：触控屏扫标签/输 8 位编码；屏幕登录后点"我的物品"；小程序一键开锁（仅本人物品，宿管可开任意） |
| 提醒 | 三色规则（红=超期 / 黄=临期 / 绿=正常），宿管单个或一键批量推订阅消息，另有每日定时自动批次 |
| 盘点 | 宿管拍一张冰箱内部照片 → 批量识别标签二维码 → 命中/台账未见/无登记 三类结果 |
| 治理 | 无主/过期物品移入待认领区 → 归还原位 或 清理留痕（事件表全程审计）；学生取出后"已取出"登记归档 |
| 容量 | 按类别先验×数量估算每件体积，宿管可逐件修正、调整总容量，页面显示占用率 |

## 功能清单

**`pi/` 树莓派端（FastAPI :8000，只主动向外轮询，不开放公网）**
- GPIO 电磁锁控制（12V 断电上锁型，高电平开锁）+ 实体应急按键（GPIO27）
- CSI 摄像头：rpicam 拍照 / rpicam-vid MJPEG 实时预览（异步广播、慢客户端丢帧）
- 本地离线分类：ONNX Runtime + MobileNetV3，仅作建议，人工确认修正
- 标签生成打印：Pillow 渲染 40×30mm@300dpi（QR+编码+名称+到期日），CUPS 直打或落 PNG
- 触控屏 kiosk（labwc + Chromium）：待机时钟屏 → 存入/取出选择 → 扫码登录 → 登记/开锁；90s 无操作自动关摄像头回待机并登出
- 后端轮询：拉取待执行开锁指令（HMAC 一次性令牌）+ 心跳上报锁状态

**`server/` 小程序后端（FastAPI + SQLite :8001）**
- 双角色：学生 / 宿管（宿管兼账号管理与系统调试）；登录强校验姓名+房间号绑定
- 台账：登记/改名/改期/取出登记/待认领/清理/恢复，全操作留痕
- 三色计算 + 多字段搜索 + 四种排序（紧急度/到期日/存放先后/占地大小）
- 订阅消息推送（开发模式打日志）、每日自动提醒批次
- 拍照盘点（原图+2x 两遍 QR 扫描）、容量与体积估算接口
- Pi 对接：`X-Pi-Secret` 鉴权的开锁指令/回执/心跳/触控屏登记与扫码登录接口
- 回归脚本 `scripts/test_planb.py`：24 项端到端断言

**`miniprogram/` 微信小程序**
- 登录页（两步式：微信登录 → 首次绑定）、学生页（我的物品管理+取出+扫屏幕登录码）、宿管页（物品/账号/调试三区）

## 硬件清单

| 部件 | 型号/说明 | 接法 |
|---|---|---|
| 主机 | 树莓派 5 8GB，Debian 13 | 官方电源 |
| 摄像头 | 官方 Camera Module（CSI） | CSI 翻盖座，银色触点朝外 |
| 触摸屏 | 官方 Touch Display 2 | DSI2（与 CSI 不冲突） |
| 电磁锁 | 12V 断电上锁型 | 12V+ → 继电器 COM，NO → 锁+，锁− → 12V− |
| 继电器 | 1 路高电平触发模块 | IN→BCM17(物理11)，VCC→5V，GND→GND |
| 应急按键 | 自复位按钮 | BCM27(物理13) ↔ GND（内部上拉） |
| 散热 | JST 4 线风扇（PWM 无效，恒速） | 建议换官方 Active Cooler |

## 快速开始

```bash
# 1. 下载分类模型（可选，缺失自动停用建议分类）
python pi/scripts/download_model.py

# 2. 后端
cd server && pip install -r requirements.txt && cp config.yaml.example? # 直接编辑 config.yaml
uvicorn main:app --host 0.0.0.0 --port 8001

# 3. 树莓派端（非派环境自动 mock 摄像头/锁）
cd pi && pip install -r requirements.txt
python app.py            # :8000，浏览器打开 http://<ip>:8000/kiosk

# 4. 小程序：微信开发者工具导入 miniprogram/，本地设置勾选"不校验合法域名"

# 5. 端到端回归（需 1/2/3 按方案B同机运行）
python server/scripts/test_planb.py
```

## 配置要点（两份 config.yaml）

| 键 | 说明 |
|---|---|
| `wechat.appid/secret` | 小程序凭据；留空=开发模式（code 直接当 openid，仅限无网络调试） |
| `wechat.dev_login` | `true` 时接受 `dev:` 前缀假 code（回归脚本用），**生产必须 false** |
| `security.pi_secret` | 派与后端共享密钥，两边必须一致；HMAC 开锁令牌签名密钥 |
| `security.jwt_secret` | 登录令牌签名，部署时必须换成强随机值 |
| `bootstrap.manager_openids` | 引导用：列入的 openid 登录自动升为宿管，配完即清空 |
| `rules.warn_days` | 临期阈值（天），决定黄/红分色 |
| `print.pi_local_api` | 方案 B 填 `http://127.0.0.1:8000`，登记即打印 |

## 上线备忘

- 当前以 **体验版** 运行：后端在内网，真机需开启小程序"调试模式"才能连 `http://内网IP`
- 正式发布需要：已备案 HTTPS 域名 + 后台配置 request 合法域名 + 订阅消息模板 ID
- 上生产前必做：`jwt_secret`/`pi_secret` 换强随机、`dev_login:false`、清空 `manager_openids`、AppSecret 泄露过就重置、:8000 端口绝不暴露公网
